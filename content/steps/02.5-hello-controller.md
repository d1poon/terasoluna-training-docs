# Step 02.5 — はじめての Controller + JSP (Hello)

## このステップのゴール

**Step 03-06 で Domain / Repository / Service / 認証基盤 を組み立てる**前に、
「1 リクエストが Controller → JSP → HTML と往復する」体験を挟む**オプションのステップ**。

- `HelloController` を `demo-web/app/hello/` に配置
- `hello.jsp` を `demo-web/webapp/WEB-INF/views/hello/` に配置
- http://localhost:8080/demo-web/hello にアクセスすると自作 JSP が返る

> 💡 このステップは飛ばしても Step 03 に進めます。
> ただし、次に画面が出るのは Step 07 まで進めた後になるので、途中で不安になったらここで小さな成功体験を挟むと良いです。

## 事前準備

- [Step 02](/steps/02-empty-boot) 完了 (Tomcat 起動確認)

```java
package com.example.demo.app.hello;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HelloController {

    @GetMapping("/hello")
    public String hello(Model model) {
        model.addAttribute("message", "はじめての画面です");
        return "hello/hello";                                                  // ①
    }
}
```

- **① `return "hello/hello"`** — `spring-mvc.xml` の ViewResolver 設定 (`<mvc:view-resolvers>` / `<mvc:jsp>`。詳細は [[/steps/07-login|Step 07]] 参照) で `/WEB-INF/views/hello/hello.jsp` に解決される

```jsp
<%@ page contentType="text/html; charset=UTF-8" %>
<!DOCTYPE html>
<html lang="ja">
<head>
    <meta charset="UTF-8" />
    <title>Hello — demo</title>
</head>
<body>
    <h1><c:out value="${message}" /></h1>
    <p>Controller から渡された文字がここに出ています。</p>
</body>
</html>
```

> `<c:out>` を使うのに `taglib` 宣言をしていない理由: `c` prefix は共通 `include.jsp` が全 JSP に自動前置するため既に使える状態にある (詳細は [[/steps/07-login|Step 07]] の「共通 include.jsp の自動前置」参照)。

## Spring Security との関係

archetype 生成直後の `spring-security.xml` は `/**` が `permitAll` で、かつ認証プロバイダも未設定 (Step 06 で設定する) なので、この時点では認証の壁そのものが存在しない。`/hello` には何もせずアクセスできる。

すでに Step 06 まで進めて認証を有効化した状態でこのステップに戻ってきた場合は、下記のどちらかで対応する。

### 選択肢 A (`/hello` を permitAll に追加)

`spring-security.xml` に:
```xml
<sec:intercept-url pattern="/hello" access="permitAll" />
```

### 選択肢 B (一時的に Security を無効化)

`applicationContext.xml` の import から `spring-security.xml` を一時的に外す。ただし Step 06 に進む時に戻す。

## 動作確認

Tomcat 起動 → http://localhost:8080/demo-web/hello に直接アクセス → 「はじめての画面です」表示 (Step 06 実施済みの場合は、上記選択肢 A/B のどちらかで `/hello` を通してからアクセス)。

## 何が起きたか (30 秒で)

1. ブラウザが `GET /hello` を送る
2. Spring Security Filter Chain が「認証済み?」を確認
3. DispatcherServlet が `@GetMapping("/hello")` を持つメソッドを探して呼ぶ
4. `HelloController#hello` が Model に文字を詰めて `"hello/hello"` を返す
5. ViewResolver が `/WEB-INF/views/hello/hello.jsp` を描画
6. JSP の `${message}` がサーバ側で置換される
7. 完成した HTML がブラウザに返る

このループが Step 07-11 で **同じ形で 5 回**繰り返されます。

## よくある詰まり

- **404 Not Found** — jsp の物理配置と `return "hello/hello"` のパスが不一致
- **`${message}` がそのまま表示される** — `<%@ page ... %>` の宣言忘れ、または EL が無効化されている
- **ログインを求められる (Step 06 実施済みの場合)** — 上記選択肢 A/B のどちらかを実行
