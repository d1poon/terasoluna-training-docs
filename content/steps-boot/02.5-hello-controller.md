# Step 02.5 — はじめての Controller + JSP (Hello)

## このステップのゴール

**まだ画面もロジックも 5 秒で書ける状態で、「ブラウザで自分の書いた文字が出る」体験を挟む**。

- `@Controller` を 1 つ、JSP を 1 枚だけ書く
- http://localhost:8080/hello にアクセスすると自作 JSP がレンダリングされる
- 「リクエスト → Controller → View → HTML」の 1 往復を、最小の 2 ファイルで体感する

Step 03-06 は Domain / Mapper / Service / SecurityConfig と、動作確認が **`BUILD SUCCESS` だけ** の地味な回が 4 連続します。
その前にここで**画面に自分の文字が出る成功体験**を挟むと、以降のバックエンド積み上げ期をモチベーション高く抜けられます。

> 💡 このステップはオプションです。Step 02 完了状態のプロジェクトを「一切壊さずに 2 ファイル追加するだけ」なので、飛ばしても Step 03 に進めます。
> ただし、次に画面が出るのは Step 07 (ログイン画面) まで進めた後になるので、途中で「ちゃんと動いているのか」不安になったらこの Step を追加すると良いです。

**リクエストを受け取ってビュー名を返すだけの、いちばん小さい Controller**。

```java
package com.example.rolemgr.controller;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HelloController {

    @GetMapping("/hello")
    public String hello(Model model) {
        model.addAttribute("message", "はじめての画面です");
        return "hello";  // → /WEB-INF/views/hello.jsp が描画される
    }
}
```

#### なぜこう書く

- **① `@Controller`** — このクラスは Spring MVC のリクエストの受け付け係。`@SpringBootApplication` の `@ComponentScan` により、`com.example.rolemgr` 配下は自動スキャンされ、この Bean が DispatcherServlet に登録される
- **② `@GetMapping("/hello")`** — `GET /hello` のリクエストが来たら、このメソッドが呼ばれる
- **③ `Model model`** — View に渡したいデータを詰める入れ物。Spring が引数として自動で渡してくれる (DI の一種)
- **④ `model.addAttribute("message", ...)`** — キー `message` で JSP から `${message}` として参照できるようになる
- **⑤ `return "hello"`** — ビュー名。`application.properties` の `spring.mvc.view.prefix` / `spring.mvc.view.suffix` により `/WEB-INF/views/hello.jsp` に解決される

**Model の中身を HTML に埋め込むだけの、いちばん小さい View**。

```jsp
<%@ page contentType="text/html; charset=UTF-8" %>
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8" />
  <title>Hello — rolemgr</title>
</head>
<body>
  <h1>${message}</h1>
  <p>Controller から渡された文字がここに出ています。</p>
</body>
</html>
```

#### なぜこう書く

- **① `<%@ page contentType="text/html; charset=UTF-8" %>`** — この JSP は「UTF-8 の HTML」を返すと宣言。日本語文字化けの最初の防御線
- **② `${message}`** — EL (Expression Language)。サーバ側で `Model` の `message` の値に置き換えられてから、ブラウザに HTML として送られる
- **③ ブラウザは JSP を見ることはない** — サーバは JSP を「HTML に組み立ててから」返す。ブラウザが受け取るのは `<h1>はじめての画面です</h1>` という素の HTML だけ

## Spring Security が有効な場合の注意

Step 02 完了時点では、Spring Security が pom.xml に入っているだけで独自 SecurityConfig を作っていないため、
**すべてのパスにデフォルトのログインフォームが表示されます** (Step 02 の動作確認で見た灰色の画面)。
このまま `/hello` にアクセスするとログインを求められます。

対処は次のどちらか:

- **選択肢 A (簡単・推奨)**: そのまま起動して `/hello` にアクセスし、デフォルトログイン画面で以下を入力
  - User: `user`
  - Password: (起動時にログに出る `Using generated security password: xxxx-xxxx-...` の値)
- **選択肢 B**: 一時的に `application.properties` に `spring.autoconfigure.exclude=org.springframework.boot.autoconfigure.security.servlet.SecurityAutoConfiguration` を追加。認証なしで見られる。ただし Step 06 に進む前に削除

Step 06 で `SecurityConfig.java` を書けば、`/hello` を `permitAll()` に追加して常時公開にすることもできます。

## 動作確認

```powershell
mvn spring-boot:run
```

http://localhost:8080/hello にアクセス (上の Security 注意に従ってログイン)。
次のような画面が出れば成功:

```
はじめての画面です
Controller から渡された文字がここに出ています。
```

### 何が起きたか (30 秒で)

1. ブラウザが `GET /hello` を送る
2. Spring Security が「認証済み?」を確認 (デフォルトフォームで認証)
3. DispatcherServlet が `@GetMapping("/hello")` を持つメソッドを探して呼び出す
4. `HelloController#hello` が Model に文字を詰めて `"hello"` を返す
5. `spring.mvc.view.prefix` / `suffix` が働いて `/WEB-INF/views/hello.jsp` が描画される
6. JSP の `${message}` がサーバ側で `はじめての画面です` に置き換わる
7. 完成した HTML がブラウザに戻る

このループがこの後の Step 07-11 (login / menu / search / userInfo / edit) でも**同じ形で 5 回**繰り返されます。
ここで 1 回体験しておくと、Step 03-06 の「まだ画面は出ないけど積み上げてる」期間の見通しが立ちやすくなります。

## よくある詰まり

- **404 Not Found**: `hello.jsp` の配置場所を確認 — `src/main/webapp/WEB-INF/views/hello.jsp` (`resources/` ではない)
- **`Whitelabel Error Page`**: `application.properties` の `spring.mvc.view.prefix=/WEB-INF/views/` / `spring.mvc.view.suffix=.jsp` が漏れている
- **`${message}` がそのまま画面に出る**: `<%@ page ... %>` の宣言漏れ、または JSP エンジン (`tomcat-embed-jasper`) が pom.xml に入っていない → [Step 01](/steps-boot/01-project-skeleton) 参照
- **ログインを求められて先に進めない**: 上記「選択肢 A」で認証、または「選択肢 B」で一時的に Security を無効化
